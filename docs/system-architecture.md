## 2. Backend modules

The backend is a **modular monolith** (see [ADR-001](decisions/ADR-001-modular-monolith.md)): one deployable API, split into modules with enforced boundaries.

| Module | Responsibility | Spec | DB schema | Route prefix |
|--------|----------------|------|-----------|--------------|
| **Identity** | Users, registration, login, sessions | SPEC-001 | `identity` | `/auth` |
| **Lessons** | YouTube URL import, captions, segmentation, user's lesson list | SPEC-002 | `lessons` | `/lessons` |
| **Practice** | Answer checking, attempts, scoring, progress | SPEC-003 | `practice` | `/practice` |

### Dependencies between modules
```
Practice ──▶ Lessons.Contracts     (reads segments to check answers)
Lessons  ──▶ (none)
Identity ──▶ (none)
All      ──▶ current user id from the auth session
```
Keep this graph up to date. If a new arrow is needed, it must point at a `.Contracts` project, and it must not create a cycle.

### Projects
```
backend/
├── Dictora.slnx
├── global.json                 pins the .NET SDK (10.0.x)
├── Directory.Build.props       settings shared by all projects

```

## 3. Domain terms

| Term | Meaning |
|------|---------|
| **Lesson** | A YouTube video a user imported, split into segments, plus their progress on it. Owned by one user. |
| **Caption / cue** | A timed piece of text from YouTube captions. This is the raw input. |
| **Manual vs auto-generated captions** | Written by a human vs generated by YouTube's speech recognition (often with little punctuation). |
| **Segment** | One sentence-level chunk of a lesson with a start and end time. The unit a user practices. |
| **Dictation** | The user listens to a segment and types what they hear. |
| **Answer check / diff** | Word-by-word comparison of the user's text with the segment: correct, wrong, missing, extra. |
| **i18n** | UI text in English (`en`) and Vietnamese (`vi`). Dictation content is English only for now. |
